# v0.9.0-rc.1 — Release Candidate 1

**Approved November 5, 2026 for testing from `main`. No release tag or GitHub release has been published.**

RC1 includes the reviewed Station interface, full-screen display, shared Focus History, optional QRZ/pyhamtools enrichment, Wavelog/ADIF history and logging, durable delivery recovery, automatic station-location matching and optional one-way UDP forwarding. It advances the package version from the earlier proposed `0.9.0-beta.1` to `0.9.0-rc.1`.

## New: see who hears you

The optional PSKReporter reception overlay adds small amber dots to the Station map for receivers that recently reported hearing **your transmitting callsign on the focus band's frequency range**. An inner amber dot in the larger focus marker means that exact station reported hearing you. All modes on the band count.

One shared TLS MQTT connection collects reports while Dashboard runs. Focus changes filter the in-memory cache without XML polling or upstream queries. Choose a 5, 15, 30 or 60-minute window; the saved default is 15 minutes. Reports expire during outages and the cache clears on restart. Incoming reports preserve map pan/zoom and never change Focus History or radio operation.

Enable **Settings → PSKReporter** after updating. Leave the transmitting-callsign override blank for WSJT-X identity, or set an explicit override. The overlay defaults off in both new and older configuration files. [Setup, exact behavior and visual preview](../pskreporter.md).

## Install and update for testing

Use the [installation guide](../installation.md) and [quick start](../quick-start.md). Installations require Git, Python 3.12–3.14 and internet access. The installer reuses compatible Node/npm or downloads a checksum-pinned temporary build toolchain for macOS/Ubuntu. PSKReporter adds the pinned `paho-mqtt` dependency; run the normal installer/updater rather than copying source alone.

For an existing clean `main` checkout, stop Dashboard, privately back up configuration/state and every configured/queued ADIF file, then run:

```sh
./update.sh
```

After **Update successful**, start Dashboard with the same configuration argument as before:

```sh
.venv/bin/python -m backend.server
```

The updater preserves saved settings and data and does not manage services. Keep a custom `--config` argument if your installation uses one. RC1 publication to GitHub does not update or restart the operating station. [Updates, backups and rollback](../installation.md#updates-and-backups).

## Evidence and remaining limits

The reviewed reception overlay passed offline collector tests, frontend tests, type checking, the production build and Chrome workflows, including desktop/mobile layout, exact inner-dot centering, band/callsign/time filtering and pan preservation. A separate built-server check verified matching dots and shared Settings across two browser clients. [The current checkpoint](../current-checkpoint.md) records the final source and exact validation results.

A 45-second receive-only subscription connected and subscribed successfully to the actual TLS broker for the operator's callsign, but received **zero reports**. Ordinary live reception-data acceptance remains pending. Reports may arrive late; no dot means no matching recent report was collected, not proof that a station cannot hear you. Other browsers, Ubuntu execution of this new feature and an extended real-broker outage have not been separately tested.

Earlier core application testing includes actual macOS station operation and operator-reported successful Ubuntu use; exact Ubuntu version/architecture and detailed acceptance evidence remain unrecorded. Full isolated Wavelog write/retry/outage acceptance and new optional-field live export acceptance are pending. Windows, Docker and MacLoggerDX integration are unverified; inline biography retrieval is deferred. Dashboard has no login system and should remain local or on a deliberately trusted network. [Full readiness checklist and limitations](../release-readiness.md).
