# Approved rebuild roadmap

The complete requirements and acceptance criteria are in [WSJTX-REBUILD-HANDOFF.md](../WSJTX-REBUILD-HANDOFF.md). That handoff takes precedence over historical project notes. Each step ends with a runnable install, checkpoint and operator review before the next integration stage.

| Step | Scope | Status |
| --- | --- | --- |
| 0 | Visual Station/Diagnostics/Settings, shared sample state, persistent preferences/history, SSE/reconnect, native installation | Reviewed and accepted; preserved in Git history |
| 1 | Configurable primary WSJT-X UDP reception; per-network-ID baselines, selection changes, bounded packet diagnostics | Reviewed; actual selections from both rigs, ordering and Decode stability verified on Mac |
| 2 | Configurable pyhamtools/callbook enrichment; background lookups, source/freshness, bounded caches | Implemented; QRZ tested by operator; photo follow-up added |
| 3 | Wavelog complete QSO history, pagination, authorized station locations including KF0TKE/KF6UFO | Implemented and reviewed on main; authenticated read-only access verified |
| 4 | Real profile/photo/license, QSO details/sorting, worked indicators, scrollable details and map | Implemented and reviewed on main through PR #3; inline biography deferred, Ubuntu acceptance untested |
| 5 | Complete shared bounded lookup history, thumbnails, retention/clear, preserved selection provenance while browsing | Implemented on `feature/steps-5-and-7`: independent observed contacts/read reconciliation, size/retention/clear controls; milestone acceptance pending |
| 6 | Optional enriched type-12 QSO delivery, independent ADIF history/logging, durable per-destination queue and mappings | Infrastructure on main through PR #4; offline validation passed, logging disabled; isolated real write validation and production cutover pending |

The operator approved the October 25 stable baseline in [the merge request](main-baseline-merge-request.md). PR #3 merged at `42220f0`; PR #4 was retargeted from Step 4 to main and merged at `e9fa332`. [Current verification and runtime state](current-checkpoint.md). Steps 0–4 are reviewed implementation, not a claim that every platform or biography capability is accepted. Future work stays on feature branches.

Step 0 reuses the predecessor's tested Vue components and snapshot transport, with a new persistent sample workspace and native installation path. Step 1 activates the receiver only when explicitly enabled in the saved TOML/Settings. It adds bounded in-memory diagnostics, per-instance health and separate persistent radio history. Step 2 adds opt-in external providers and server-side credentials; Step 3 adds opt-in read-only API v2 history across all authorized locations, with complete pagination and safe partial/error states. Step 4 supplies the compact profile/details/map/contact display. The optional QSO extension adds independent ADIF history and disabled delivery infrastructure. Production WaveLogGate remains the uploader. No isolated Wavelog test instance currently exists; production data is not a write/retry/outage test target. Its absence does not block publication of disabled infrastructure. Forwarding is not implemented.

One process owns displayed focus and history; latest accepted server interaction wins across browsers. History is bounded at 200, deduplicated by callsign. Sample selection updates rig/time/band and moves the entry first. Browsing changes only displayed focus/browsing time. Complete snapshots coalesce in bounded one-item queues (maximum 32 streams), heartbeat every 15 seconds; reconnect includes a full snapshot and epoch/revision guards. Slow clients skip intermediate snapshots. Independent fixture lookups use generation guards. Step 1 connects actual UDP selections to this foundation; telemetry snapshots are coalesced at 5 Hz while selection/browsing/preference updates publish immediately.

`config.toml` owns installation/network configuration; `data/workspace.sqlite3` beside that file owns validated browser preferences and selected sample history. The original sample workspace and new live_workspace tables each use schema version 1; unknown versions fail rather than overwrite data. This is application workspace state, never an authoritative QSO log. One worker only, no reload in installed operation. Synchronous SQLite commits are small/bounded and occur only when persistent focus/history/preferences change, never for ordinary Decode/telemetry traffic. Diagnostics retain at most 500 raw datagrams in memory, with 100 rows rendered per browser page. Back up with the server stopped. Step 0 TOML files are read with defaults for new keys and are never rewritten by installation. Receiver saves replace only receiver fields atomically, preserving HTTP configuration and comments. Step 0 sample state/preferences are preserved; live history starts independently. No predecessor memory-only history can be migrated.
